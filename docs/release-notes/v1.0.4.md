## PS5X360Reloaded v1.0.4

The second release built from source. The home screen shows `PS5X360Reloaded v1.0.4`. It is installed and updated like v1.0.3 (`PPSA83600.ffpkg`, `.ffpfsc` or `.zip`; the whole `PPSA83600` folder, not `eboot.bin` alone). Its `contentVersion` is `01.004.000`, so the console sees v1.0.3 as an older install.

**How to read the status tags below:**
- `[console]`: confirmed on PS5 on a `1.0.4_candidate_N` build; the candidate is named.
- `[host tests]`: verified by tests on a computer (`tools/check-*`, run in CI), not confirmed on the console.
- `[no separate test]`: the code was in the candidates tested on the console, but nobody checked this change on its own.

### Library and storage
- **Games copied to the app's own folder are found with every kind of install** (issue #12, fix 60) `[host tests]`:
  - With an image install (`.ffpkg` / `.ffpfsc`), games copied to `/data/homebrew/PPSA83600/assets/roms` were not listed, although the empty library said to put them there. That folder is now scanned.
  - A `game_paths.txt` from an earlier version gains it once; nothing in it is removed or reordered. One folder reached by two names is scanned once.
  - The empty library also names the other folders it scans: `/data/xbox360/` and an `xbox360` folder at the top of a USB or M.2 drive (both themes, every language).
- **The saves folder on external drives is `<drive>/PS5X360Reloaded/saves`** (fix 50):
  - An old `<drive>/PS5X360/saves` is moved there once `[console, candidate 9: /mnt/ext1/xbox360/PS5X360/saves moved, saves load]`.
  - If both exist, profiles and per-game folders found only in the old one are moved over; nothing in the new one is overwritten `[host tests]`.
- **Multi-disc games swap discs in game** (fix 51) `[console, candidates 14 and 31]`: Battlefield 3 goes from Disc 1 to the campaign on Disc 2; the sibling image in the same folder is used.
- **The library tells discs apart** (fix 52) `[console, candidate 14]`: "… (Disc 2)" stays in a tile's name, and the details line says "Disc 2".

### Games
- **Ninja Gaiden II (`544307D5`) runs** (issue #11; fixes 65, 67, 71):
  - Before: the app closed with the system's own error dialog about 10 seconds into play. When the game cleared an XMA audio context, the emulator, still inside its own fault handler, wrote to memory the GPU was watching; that second fault ended the process.
  - A fault inside the fault handler is now handled (fix 65), and the audio context write lifts the watch first (fix 67) `[console, candidates 23, 26, 29 and 31: up to 9.5 minutes of play, 50–60 FPS, sound right]`.
  - A black screen after a few minutes (two of the game's job threads suspended themselves just after being resumed and were never woken) is fixed by keeping such an early resume for the suspension that follows (fix 71) `[host tests: the hang reproduced and gone in a stress test; console, candidate 31: 9.5 minutes at 60 FPS without a black screen]`.
- **Call of Duty: Modern Warfare 2 and other games with the fast resolve readback** no longer stall the GPU thread waiting for the previous copy (fix 59) `[console, candidate 22: MW2's 138 ms/s of waiting gone]`.
- **Battlefield 3 and Call of Duty**: the GPU command thread spins briefly instead of sleeping on the emulator's global lock, and requests for data already on the GPU skip it (fix 55) `[console, candidates 16+]`.
- **Call of Duty: Black Ops: skinned characters' hair** (issue #10, fix 48): memory-export data is no longer lost when the GPU copy is uploaded over it; the green and grey glow on the hair is gone `[console, candidate 7]`.
- **Tekken Tag Tournament 2 (`4E4D0859`) no longer slows down in fights** (issue #13; preset): its preset now uses the fast resolve readback instead of the complete one. No 1–2 second stalls at each new fighter or stage `[console, candidates 21 and 31 with the setting chosen by hand: 45–50 FPS on 21, 56–58 on 31; the preset file itself: host tests]`.
- **Dragon Ball Z for Kinect with a phone as the sensor** (fixes 57, 63, 64) `[console, candidates 21, 23 and 24: 8.5 minutes without a crash]`:
  - The virtual Kinect finds Kinect games by their NUI code; DBZ registers its identity callback, binds the skeleton and gets about 30 frames a second from the phone.
  - DBZ no longer crashes after about two minutes: a mutant (lock) made for a guest structure was created anew at every use, leaking a host lock each time (fix 64, a core fix for every game).
  - While no phone is connected, the in-game motion panel shows the camera QR code and the pairing key (fix 63).

### Kinect with a phone
- **Pairing a phone as the Kinect sensor is one guided flow** (fix 56) `[console, candidates 24 and 25]`:
  - The phone page opened from the TV's QR code connects by itself and says what it is waiting for (start the Kinect game, or turn on Camera motion).
  - It pairs and starts the camera when the game starts, and reconnects after the console restarts into the game.
  - One status banner, a layout for any phone, the page in your language (Polish added); the pairing key is shown large next to both QR codes and is not case-sensitive.
- **The phone page shows its delay by stage** (camera, detection, sending, network, hand smoothing), and the console logs it every 2 s while paired (fix 66) `[console: camera and detection stages logged every 2 s after reloading the page]`.
- **A phone page left open while the app was updated reloads once by itself**, so it runs the console's current page (fix 72) `[host tests]`.

### Performance and diagnostics (for bug reports)
- **"Measure performance" in the guide samples for 10 s** instead of 5 s (fix 54) `[console]`.
- **The 30-second summary says where frame time goes** (fixes 49, 58, 62) `[console, candidates 20–23]`: GPU busy time; the GPU command thread's work by kind (draws, resolves, submissions, uploads, textures); its waits by cause and by the line that waited; and what uploads spend on barriers, buffers, marking memory valid and copying.
- **A game that ends silently now leaves a report** (fixes 47, 61, 65, 69) `[console]`:
  - `logs/hang-watch-<TITLEID>-<time>-UTC.txt`, one per run, the newest 12 kept: a heartbeat every 250 ms with memory use, the last guest kernel calls and which thread waits for what.
  - Faults on an exhausted stack and faults inside the fault handler are reported (alternate signal stacks); the crash report goes to the game log instead of staying in `boot.log`.
  - The stall report lists each thread's recent suspensions and resumes, and the log names resumes that reach a thread before it suspends itself `[console, candidate 29]`.

### Known limitations
- Everything listed for v1.0.3 still applies (Vulkan only; not byte-identical to the official 1.0.2; `/download0` settings do not carry over).
- 1.0.5 work in progress, not in this release: "Deferred memory watches" (fixes 68, 70; no measurable gain in Modern Warfare 2 yet) and the Kinect tuning for DBZ (body scale, panel position).
- Kinect with a phone is research quality: DBZ reaches gameplay, but the in-game hand control still needs tuning (planned for 1.0.5).
