## PS5X360 v1.0.3 (first release built from source)

The first PS5X360 release whose `eboot.bin` is **compiled from published source**, rather than the official 1.0.2 executable with binary patches (as in `v1.0.2-opt` and `v1.0.2-opt-r2`). The home screen shows the label `PS5X360 v1.0.3`.

### What this release is
- **Built from source:** `tools/source-1.0.2/assemble.py` assembles the tree from the PS5X360 author's public source packages (BrinooTk: `0.5.9-fix1`, `0.6.0`, `1.0.0`, `1.0.2`), the Xenia Canary netplay core (`AdrianCassar/xenia-canary`, commit `d2cf527aa`) and a few reconstructed headers. Our fixes from `tools/source-1.0.2/fixes` (01–13 and 20–30) are applied on top. Details: [`docs/SOURCE-1.0.2.md`](https://github.com/grzegorz2047/PS5X360Reloaded/blob/v1.0.3/docs/SOURCE-1.0.2.md).
- **GPL-3.0 license:** the executable links wolfSSL and ps5-framegen (both GPL-3.0-or-later), so the whole is distributed under GPL-3.0. The release includes the source tree `eboot.bin` was compiled from and the build scripts (see *Source code*); the source of the toolchain and of the statically linked RADV/Mesa and PS5 runtime is in the `mihawk-99` repositories at the commits listed there. PS5X360 code stays under MIT, Xenia under BSD-3-Clause. The license files are in the package under `licenses/`: a new notice `PS5X360-1.0.3-NOTICE.txt` (source build, GPL-3.0) and added texts of GPL-3.0, Mbed TLS, MPL-2.0 (CA certificates) and the full miniupnpc license; the official 1.0.0 notice is kept as provenance.
- **Vulkan only:** the OpenGL renderer from the official 1.0.2 was never published, so it is not included (#6). Choosing OpenGL in a game's settings falls back to Vulkan.
- **Not byte-identical to the official 1.0.2:** this is a reconstruction. `eboot.bin` is about 22 MiB smaller, almost entirely because the OpenGL stack is missing. The full list of gaps is in *Known limitations*.
- **The other package files** (assets, configs, fonts, `sce_sys`, `sce_module`) come from the official `PPSA50011` v1.0.2 package, except the language files (fix 25), the presets, configs and game patches from this repository (see *Game presets*), and the `VERSION`, `RELEASE.json`, `MANIFEST.json` and license files.

**How to read the status tags below:**
- `[console]`: confirmed on PS5 on a candidate built from source (`1.0.3_candidate_N`); the candidate is named.
- `[console, binary]`: confirmed on PS5 only in a binary-patched build (r2 or a later test build), not separately in this build.
- `[host tests]`: verified by tests on a computer (`tools/check-*`, run in CI), not confirmed on the console.
- `[no separate test]`: the code was in every candidate tested on the console, but nobody checked this change on its own.

### Game fixes
- **Battlefield 3 (`45410950`) works** (fix 30 + built-in preset) `[console]`:
  - Previously the game hung after a level started (on the official 1.0.2 too): a GPU memory export (memexport) that unblocks a rendering job stayed in the GPU-side copy of memory, and no game thread ever saw it.
  - Memory-export readback now writes to guest memory only what the shader actually changed. Small exports (up to 64 KiB) are always read back.
  - The built-in preset enables `memexport=1` (full export readback) for BF3. This is what makes the game work: BF3's export range (384 KiB) is larger than the small-export limit.
  - On the console: `1.0.3_candidate_36` reached the menu and levels at 25–28 FPS without hanging (with `memexport` set by hand). `1.0.3_candidate_37` (the same fixes as this release) runs BF3 with `memexport` enabled through the player's own setting. The built-in preset on its own is verified by a host test (`check-bf3-preset.py`); it has not yet been tested on the console without the manual setting.
  - BF3 diagnostics (log probes) are active only with verbose logging.
  - BF3 also needs fix 20 (below): the `ClientLoad` thread waits for `ServerLoad` to actually finish.
- **Handball 16 (`573607E4`) starts and gets past the START screen** (fix 26) `[console]`:
  - File names in Windows-1252 encoding on the disc (e.g. `ó`) no longer break mounting the image ("Not enough space"). Applies to GDFX, STFS and SVOD images.
  - Added `XTLGetLocaleV1`; system dialogs release the UI lock; `DeleteFile("")` gets an immediate answer instead of going through the file system.
  - On the console: `1.0.3_candidate_26` gets past the title screen and loads the teams and the stadium at about 50–57 FPS. The test was on a version with extra diagnostics; the final fix (without those diagnostics) was not tested separately on Handball 16.
- **Naruto: The Broken Bond (`55530825`) no longer closes at startup** (fix 28) `[console]`:
  - The sign-in notification for a new System|Live listener is held back until its first `XNotifyGetNext` (previously a crash at `827F9D74`).
  - Fixed the `SO_DONTLINGER` / `SO_EXCLUSIVEADDRUSE` socket options.
  - On the console: `1.0.3_candidate_23` runs without a crash and the game gets to the save-location prompt. Candidate 23 did not yet have some of the later fixes (including 21, 26, 29 and 30); Naruto has not been tested with this full build.

### Game presets (package data, `assets/presets.txt`)
The package takes `assets/presets.txt`, `assets/config` and `assets/patches` from this repository at the release commit (`tools/source-1.0.2/package.py`). Changes from r2:
- **Battlefield: Bad Company (`454107F9`):** no FSI (`accurate_targets=0`), `readback=0`, `pipeline_threads=3`. Shader compilation about 3× faster, a stable 60 FPS `[console, binary]` (tested 2026-11-19 on the official eboot with binary patches).
- **Fable II (`4D5307F1`):** restored the preset from the official 1.0.2 (`clear_pages=1`, `readback=1`). The `fast_locks`, `memory_boost`, `dynamic_buffers` and `fast_dot` flags from r2 made the game ignore the controller.
- **Fable III (`4D5308D6`):** preset, config and optional patches unchanged from `v1.0.2-opt-r2`.
- The `readback-auto.off` file is no longer added to the package (in r2 it darkened the image in BF: Bad Company).

### Emulator and UI changes

#### Fixes 01–13: binary patches from the `v1.0.2-opt` line, now in source code
Fixes 01–05 were in `v1.0.2-opt-r2` as binary patches. Fixes 06–13 were made as binary patches after r2 and were never released in binary form; this is their first release. What is carried over is the intent of the patches, not the machine code; the differences are described in `docs/SOURCE-1.0.2.md`.
- **01 JIT:** no unnecessary `mfence` barriers around `lwarx`/`ldarx`/`stwcx.`/`stdcx.` (`stwcx.` with a 32-bit type in `StoreWithReserve`, a cosmetic change). Same as r2. `[no separate test]`: in candidates since `candidate_1`, except `candidate_19` and `candidate_30`, which were deliberately built without it. Not the cause of the BF3 problem.
- **02 `mprotect`:** no `clock_gettime` pair around every `sceKernelMprotect`. Unlike r2: with GPU diagnostics enabled the timings come back (without them, protection times show 0; the call counters still work). `[no separate test]`
- **03 Access violations:** no copying of 256 B of XMM registers on `SIGSEGV` (write-watch, MMIO); general-purpose registers are still copied. Same as r2. `[no separate test]`
- **04 GPU command thread** on its own core (CPU 2, with the sibling CPU 3 left free). Same as r2 (#4). `[no separate test]`
- **05 FSI choice files** in the writable `/download0/xbox360ps5` (`fsi.c`, `fsi.1`, `fsi.c.new`): ends the FSI restart loop on `.ffpkg` images. The same names as in r2, so the choice carries over between versions; without `fsi.c` the old `/app0/render-target-fsi.conf` is read. Affects 56 games with `accurate_targets=1` in the presets and games with FSI enabled in their settings. `[console, binary]` (r2, BF: Bad Company); not tested separately in this build.
- **06 Shader, module and `utility-cache` cache** in `/data/homebrew/PPSA50011/cache` (previously `/app0/cache`, which is read-only on `.ffpkg`, while writing to `/download0` ran out of space, e.g. in Halo: Reach). `/app0/cache` remains as a fallback location. The cache path is confirmed in the `candidate_37` log; the cause of the out-of-space error was diagnosed on the console, but nobody separately checked that the error is gone.
- **07 Vulkan cache save on exit** waits up to 30 s instead of 1.5 s (a large cache is no longer left behind as an unfinished `.vk.bin.pending-0`). `[no separate test]`
- **08 Selective pipeline wait:** with background shaders (`async_shaders`), draws that overwrite RT0 (a full-screen quad of up to 6 indices, or a target up to 256 px wide) wait for the proper pipeline. Other draws still use the placeholder. `[console, binary]`: in BF: Bad Company the purple surfaces and the purple reflection cube disappeared; not tested separately in this build.
- **08b Priority:** pipelines for full-screen quads and small targets (the ones fix 08 may wait for) compile first (priority 4). `[no separate test]`; it was present together with 08 in the binary BF: Bad Company test.
- **09 The "No new frames (compiling shaders or loading)" message** appears after 2 s instead of 45 s. `[no separate test]`
- **10 VSync on** (with no game patch disabling VSync) limits `VdSwap` to about 60/s (a 16.60 ms grid), so games with a 60 FPS patch do not speed up. The problem was seen on the console (BF: Bad Company above 80 FPS); the fix was verified by disassembly in the binary version, not confirmed on the console.
- **11 `framegen.conf`** is read and written first in `/download0/xbox360ps5`, so frame generation can be enabled on an `.ffpkg` install. Without the new file, the one from the package is read. Not confirmed on the console.
- **12 A third background-shader option: "On (experimental)".** Placeholder pipelines with color output are invisible (no color, depth or stencil writes). Draws of up to 6 indices with depth testing enabled (billboards, decals) do not wait for their pipeline; full-screen passes and small targets still wait. Not tested on the console: the mode is active only when the option is selected by hand.
- **13 "FSI (per game)" option:** off, standard (the game's preset or the general FSI switch) or on. On the console only the default value is known to work; forcing it on or off has not been tested.

#### Fixes 20–29: new in the source build
(Fixes 26, 28 and 30 are described above, in *Game fixes*.)
- **20 Stale kernel object headers** (event, mutant, semaphore, thread) get the right object instead of none. In BF3, `ClientLoad` waits for `ServerLoad` to actually finish (a join, as on the console) instead of getting a falsely signaled substitute. `[console]` for threads (BF3, `candidate_6` and `candidate_36`); event, mutant and semaphore `[host tests]`.
- **21 PS5 home screen forwarders:** a game launched directly from a tile (full path, `--rom <game>` with a path, folder or title ID) and `--exit-after-game` (closing the game returns to the PS5 home screen). Port of BrinooTk/PS5X360#62. `[console]` (`candidate_34`): a tile from Forwarder Manager launched Army of Two by full path, with and without `--exit-after-game`; the `--rom` and title ID forms `[host tests]`. Description: [`docs/FORWARDER.md`](https://github.com/grzegorz2047/PS5X360Reloaded/blob/v1.0.3/docs/FORWARDER.md).
- **22 "Network" row in the guide** (off / System Link / Online): change the network mode during a game without restarting. On the console only the first version was tested (`candidate_3`, Black Ops III), and it exposed bugs; the reworked version `[host tests]`, not confirmed on the console.
- **23 Missing UI translations** are shown in English instead of Portuguese. `[host tests]` (later extended by 25).
- **24 Hang diagnostics:** an extended `STALL` report (code around `lr`/`ctr`, stacks, object history, GPU command processor state, BF3 probes). It changes only the logs; BF3 probes are written only with verbose logging. Used on the console in candidates 6–31 to diagnose BF3.
- **25 English as the UI source language:** the language files are now keyed in English (16 files, including a separate `pt-BR.txt`); fixed Portuguese leaking into other languages (game card, "Network" row, option counter). `[host tests]`; the fix is in the candidates tested on the console since `candidate_7`, but the UI language was not checked separately on the console. **This affects installation, see below.**
- **27 Save drive choice** `[console]`:
  - When a game asks where to save, all writable drives are listed: the internal folder, `ext0`–`ext3` (M.2 / extended storage) and `usb0`–`usb7`. Each drive keeps saves in its own `PS5X360/saves` folder.
  - The choice is remembered per game; new "Save drive" option (global and per game).
  - On the console: first version in `candidate_13`; the scan that closed the game in `candidate_24` was fixed in `candidate_27`; in `candidate_29` the remembered choice works (Fable Anniversary does not ask a second time); in `candidate_36` a USB drive with only the system `System` folder is not offered.
- **29 Online / System Link on a fresh install:** the missing folder for `network.conf` is created (previously "Could not write network.conf." on an install from the package; BrinooTk/PS5X360 issue 111), and the cause of the write error goes to the log. `[host tests]`; switching the network mode on the console has not been tested with this build.

### Installation
Release files (the same kinds as in r2):
- **`PPSA50011.ffpkg`**: UFS2 image for etaHEN / ShadowMountPlus.
- **`PPSA50011.ffpfsc`**: compressed PS5 PFSC image.
- **`PPSA50011.zip`**: the `PPSA50011` folder to copy over FTP to `/data/homebrew/` (checksum in `PPSA50011.zip.sha256`).
- Game patch files (`*.patch.toml`, e.g. Fable III) from the repository, as in r2; also included inside the packages above.
- **`SHA256SUMS.txt`**: SHA-256 checksums of all release files.

Image (`.ffpkg` / `.ffpfsc`): replace the previous PS5X360 image file with the new one in the same location ShadowMountPlus mounts it from, and restart PS5X360. Settings saved in `/download0/xbox360ps5` are not part of the image.

ZIP: extract it and copy the **whole** `PPSA50011` folder to `/data/homebrew/`, overwriting existing files. Do not delete the `saves`, `cache` and `logs` subfolders from the previous install. The executable must be at `/data/homebrew/PPSA50011/eboot.bin`.

> **Note: do not replace only `eboot.bin`** in an existing 1.0.2 or r2 install. This `eboot.bin` reads language files keyed in English (`PPSA50011/assets/lang/*.txt`, 16 files including `pt-BR.txt`). With the official files (keyed in Portuguese) the whole UI will be in English regardless of the selected language. Conversely, the r2 `eboot.bin` does not match the language files from this release. Always install the whole package; to go back to r2, use the whole r2 package as well.

### Known limitations
- **No OpenGL renderer** (#6): Vulkan only. Games that ran better, or only, on OpenGL in the official 1.0.2 run here on Vulkan or not at all.
- **No games from the PS5 disc drive** (#7): a disc in the drive does not appear in the list, and the `disc-helper.elf` relay does not work.
- **No physical USB Kinect or its relay** (#8): only the phone Kinect (and the virtual one) works.
- **Smaller gaps compared with the official 1.0.2** (#9): no input diagnostics, network self-test or cover download log; several headers are reconstructed (button hint colors, dark theme, `gameinfo.txt` reader, list of 17 languages). The dark theme and the game info card are not documented as confirmed on the console.
- **Compiler flags** (#2): the title objects are compiled with the flags from 0.5.9 (`-O2 -mavx`), the core with `-O3`; no ThinLTO.
- **JIT optimizations from newer Xenia Canary** (#5) are not included; from that series only the barrier part is in (`lwarx`/`stwcx.`, fix 01).
- **Forwarders and ShadowMount+:** when the forwarder launcher is already running, ShadowMount+ may refuse the start (`0x80940033`, bug [drakmor/ShadowMountPlus#196](https://github.com/drakmor/ShadowMountPlus/issues/196)). Workarounds are in `docs/FORWARDER.md`.
- **Battlefield 3** runs at about 25–28 FPS.

### Source code (GPL-3.0)
- **`PS5X360-1.0.3-source.tar.xz`**: the full tree this `eboot.bin` was compiled from (the output of `assemble.py` with the fixes applied, version `1.0.3`): the Xenia Canary netplay core, network libraries (wolfSSL, libcurl, miniupnpc), Mbed TLS, title code, reconstructed headers, license files and `SOURCES.json`. `SOURCES.json` records the SHA-256 checksums of the author's source packages, the core and library commits, the origin of every title file and the applied fixes.
- **`PS5X360Reloaded-1.0.3-scripts.tar.gz`**: the build scripts, i.e. this repository at the release commit (the tag's "Source code" archive on GitHub contains the same): `tools/source-1.0.2` (`assemble.py`, `build.sh`, `fixes/`, `english/`, `reconstructed/`), `tools/build-radv-platform.sh` and the workflows `.github/workflows/build-source-1.0.2.yml` and `release-source.yml`.
- **`SOURCES.json`** and **`PS5X360-1.0.3-build.log`**: a record of this build's inputs and the compile log.
- **`PS5X360-1.0.3-toolchain-source.tar.xz`**: the source of the toolchain and the statically linked libraries (RADV/Mesa, the PS5 runtime from PS5_Vulkan and the payload SDK) at the commits this build used (without `.git`, with a `PINS.txt` file). The same is in the repositories: `mihawk-99/PS5_Vulkan` `3f3ee69607013b345d2baa6d6a37c86745649a08`, `mihawk-99/PS5_Mesa` `0b2d6d1a61d9bbf89cf8beb88a696144f67c61f8` and `mihawk-99/PS5_PayloadSDK` `95c08f27386fc698f6bbe21dde3030140a41d10b`.

**How to rebuild:**
1. Extract `PS5X360Reloaded-1.0.3-scripts.tar.gz` (or the "Source code" archive of the `v1.0.3` tag) and set up the toolchain the way the steps of the `build-source-1.0.2.yml` workflow do (Ubuntu 24.04, clang/lld 18, Vulkan SDK 1.4.341.1 for the shader tools, the three `mihawk-99` repositories at the listed commits in `.deps/references`, RADV built by `tools/build-radv-platform.sh`).
2. Extract `PS5X360-1.0.3-source.tar.xz` (or assemble the same tree from scratch: `PS5X360_BUILD_VERSION=1.0.3 python3 -I tools/source-1.0.2/assemble.py --out build/src102`, which downloads the source packages and the core at the recorded versions).
3. Build: `bash tools/source-1.0.2/build.sh <tree> build/src102-out`. The output is `build/src102-out/eboot.bin`. Host tests: `bash tools/source-1.0.2/run-fix-checks.sh <tree>`.
